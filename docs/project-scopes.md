# 项目作用域改造

## 问题与边界

原实现有意只创建 global 会话，导入固定写入默认项目，数据目录和 workspace.current 都查询全库。分类草稿入口存在，但“从工作台已保存标注建方案”的自然语言没有稳定路由，缺少本轮导入记录时还会收集全库标注。两项问题必须一起解决。

项目保存资源归属；会话不可变地绑定一个项目；实验保存实际输入、标注副本、划分、参数及评价口径。画布选中对象、context_json、模型工具参数均不能修改会话的项目身份。这是同一桌面应用内的数据边界，不是新增多账号权限体系。

## 实现约定

1. `agent_session.project_id` 是外键。旧会话归默认项目；触发器拒绝无项目的新会话及项目身份修改。`agent_session_scope` 原有幂等/历史快照职责不变。
2. `desktop_project` 持久化当前项目。原生工作台页面使用请求开始时的选择；会话请求及 SSE 每次推进使用会话绑定。切项目进入该项目历史或空会话，不携带旧画布、卡片和目录。
3. `projects.py` 提供项目身份、父资源追溯及拒绝函数。HTTP、工具和领域 getter 都校验，列表过滤不能替代编号校验。拒绝不返回外项目归属、名称、数量或路径。
4. cube → 标注/预处理，cube 数组 → 训练，训练 → 注册模型/评价，评价 → 分类导出。任务回执、取消、缓存和文件下载同样遵守父链。连续量与标签都限定项目。
5. 自建配方创建时关联当前项目；读取/修改/版本引用须关联。内置公共模板可读、可执行，不能原地修改。取消关联的自建配方不在重启时被默认项目收编。
6. 本机 ENVI/ROI/NPZ 实验也归项目。新实验和 Study 通过 `project_resource` 记录归属；不重写已有 config、模型、预测或报告字节。历史实验文件归档保留默认项目兼容读取；历史 Study 按可信会话补索引，不使用默认项目兜底。
7. 同项目重复导入复用已有登记；同路径已登记在其他项目时拒绝，保持全局路径唯一约束。第一版不提供隐式共享可变标注或跨项目模型复用。
8. 普通名称创建复用大小写同名标签；自定义 code 和改名不能制造新的同名标签。历史重复保留并报歧义。中英文别名仍需用户明确声明，不自动翻译或合并。
9. 线程提交捕获项目上下文，标注队列按任务会话重新绑定。启动恢复允许内部跨项目遍历，不向模型或接口开放绕过开关。

完整 SQL 审查位置及动态资源入口见 [资源清单](project-scope-inventory.md)。

## Study 确认失败与资源生命周期

非默认项目下的“确认探索性寻优”失败源于生命周期：原来草稿未登记归属，确认事务才插入 `project_resource`；随后 `Study.folder()` 打开第二个连接校验，该连接看不到未提交的 INSERT。确认事务回滚，归属表仍无该记录。结构化 `study_id` 请求也会在进入业务处理前被拦住。默认项目的无索引回退让这类缺陷在旧用例中不可见。

现在创建草稿时，在同一事务中写入归属、草稿和待确认回执；提交后才向用户展示方案。确认只使用已经登记的归属，后台线程继承会话项目。登记可在同一项目重复调用，其他项目登记相同 ID 会被拒绝，不能使用忽略冲突来隐藏不同归属。保存失败会整体回滚，不留下仅有归属的半成品草稿。实验创建登记失败也会释放数值锁，避免影响下一次训练。

启动时，从 `study_draft.session_id → agent_session.project_id` 补齐旧草稿；不再是当前草稿的历史任务，从 `status.json.session_id` 关联实际存在的会话。只补缺失索引，不覆盖已有归属，不改 revision、确认回执或归档内容。非法编号、缺失会话及多个项目争用同一编号时不自动归属。历史任务中断恢复仍沿用原有机制。Study 在默认项目同样需要明确归属，未知编号不能因默认项目而放行。

项目、会话、实验继续保持三个职责：项目管理资源归属；同项目可有多个会话；会话保存草稿、待确认动作和任务回执；实验冻结输入及配置。导入必须有项目归属，但无需强制用户先手动命名一个项目，已有当前项目/默认项目机制可满足快速使用。切换桌面项目不改变已有会话、后台任务或模型的归属。本次不增加跨项目共享或移动真实数据。

全局路径唯一是当前兼容约束，不代表长期必须复制大体积 ENVI 才能复用。未来确有跨项目复用需求时，可以分离只读原始文件和项目内的数据实例、标注及实验，通过显式引用共享原始字节；不能因此共享可变标注或让调用者隐式改归属。本次保留既有唯一约束。

每种资源都必须在创建时具备可追溯的项目归属，但不需要给所有子表重复增加 `project_id`：

| 资源 | 创建时归属 | 访问边界与验证 |
|---|---|---|
| 数据 | Registry 登记行的 `project_id` | 列表过滤、`Registry.get`、跨项目同路径拒绝 |
| 标签、连续量 | 行的 `project_id` | 同项目查重、编号及别名校验 |
| 自建配方、版本 | 配方与 `project_recipe` 同事务；版本追溯配方 | 列表及持有 `recipe_id` 的直接调用；公共模板只读例外 |
| 标注、预处理 | 创建时校验 cube；通过 `cube_id` 继承 | 保存、读取和任务均验证父数据 |
| 旧建模训练、注册模型、评价 | 训练冻结 cube 数组；模型/评价引用训练 | 校验全部 cube 与模型父链，不能跨项目注册或推理 |
| 统一实验及其模型/报告 | 开始写归档前，先提交 experiment 索引 | 详情、模型加载、缓存、下载及后台均验证实验归属 |
| Study | 草稿、study 索引、确认回执同事务 | 审阅、确认、结果、取消与采用均保持项目/会话边界 |
| 推理 | 原生推理引用 cube 和模型；统一推理继承已校验模型归档 | 新 cube 与模型都校验；任务回执保留会话边界 |
| 接入卡、参数草稿、任务回执 | 引用不可变项目会话 | 恢复沿用原会话；前端选择或 context_json 不能改归属 |

新增模型应复用这些输入、训练产物及归属边界；不应在模型算法内部另造项目身份。具体 SQL 清单与动态入口审查互补，不能只测列表隐藏。

## 对话行为

项目列表的“新建项目 / 管理项目”位于当前项目内容之外。管理页提供删除预览：显示项目名称、数据/对话/标签/配方/实验与寻优记录数量，要求输入名称确认。预览令牌绑定这些数量；发生变化须重新预览。删除是可恢复的移入回收站，不删除原始文件、标注、审计行、训练模型或报告；不提供永久清除。

`project_trash` 保存删除时间。正常项目列表排除这些项目，旧会话入口、资源编号和再次选择都拒绝访问。恢复沿用原项目及全部资源编号，不自动切换当前项目。删除当前项目在同一事务内切换到其他可用项目，最后一个可用项目不可删除。前端清理当前对话、画布与数据目录后再载入替代项目；管理页可刷新列表，核对响应中断后的实际状态。

删除前检查该项目全部对话及其后台队列，而非只检查当前对话；事务内再次核验请求、实验任务、预处理、训练、推理以及桌面分类训练队列。内存队列检查在数据库写锁之前进行，避免与工作线程锁顺序相反。后台任务仍运行或排队时拒绝删除；另一个项目的任务不阻塞无关项目。

原生 HTTP 操作及 SSE 使用按项目记录的活动租约，覆盖响应全过程；删除先取得排他变更标记，防止检查后又进入新请求。管理请求不把自己算作后台工作。锁仅保护内存计数和变更标记，不跨数值计算持有；数据库与工作线程的队列锁不反向嵌套。

智能助手左侧按“当前项目 → 本项目的对话”展示层级。项目选择始终可见；新建对话沿用项目数据，独立保存消息和方案。另一项独立课题可新建项目；继续未完成步骤应打开原对话。右侧上下文和常驻输入条只显示范围摘要，避免在多个位置提供项目切换控件。

对话标题和输入区持续显示当前项目，数据接入卡显示所属项目。新对话提供导入目录、查看项目数据和查看项目模型/结果的入口；前两个只填写消息，仍需用户发送。导入记录归属项目，不意味着复制原始文件；具体训练范围以方案卡的冻结名单为准。项目数据数量使用完整目录的就绪状态，未核对或切换中不显示旧数量。

推理方案的可编辑状态由服务端给出：`active=1 AND run_id IS NULL` 才可编辑；已执行记录及已关闭草稿只读，卡片隐藏微调、前景操作和确认执行入口。缺少状态字段的旧卡片也默认只读，不从“这是最后一张卡片”推断可编辑。

已执行后再次输入推理请求，会展示“新建推理方案 / 查看上次推理结果”。新请求保存在会话所属的 `inference_restart_request`，不改原草稿、历史 run 或产物。按钮携带修订号和请求令牌，不能用旧按钮误执行后来暂存的请求。选择查看结果会丢弃待新建请求；选择新建才将草稿设为 active、清空 run/审阅记录并增加修订，再解释本次模型与路径。没有暂存输入时，明确新建会复制原方案作为可编辑起点。新草稿仍需审阅和单独确认才执行；已有结果文件不改写。

“使用当前已标注数据新建训练方案”及“用已导入数据新建分类训练方案”等明确请求进入同一工作台接入逻辑。只收集当前项目或明确指认范围的已保存标注，复制原始标注，不运行预处理、不训练。类别来自实际使用的保存标注，不从所有项目标签或文件夹猜测。

`agent_step_plan` 保存用户明确要求逐步确认的 `【第1步】…` 计划。只释放当前步骤给路由；报告后等待确认。后续包含“划分/Study/训练”等关键词不会提前改变本轮意图。不得跳步；本步后台任务未结束时不能进入下一步。草稿已成功写入但还有其他阶段的待补字段时，仍能报告本步写入事实并等待下一步。

用户禁止默认参数时，工作台接入不填预处理和模型配置；这些字段显示待补充。计划状态不替代原有数值任务审阅与确认：训练、Study 和推理的原生提交也校验当前获准步骤。

## 迁移与交付

结构迁移前，如果检测到旧版已有会话的数据库，先通过 SQLite backup API 创建一致性备份：

`db/backups/before-projects-<唯一编号>.sqlite3`

备份包含 SQLite 所见的已提交 WAL 内容，不依次复制写入中的 main/WAL/SHM。备份失败则不继续项目结构迁移。空的新工作区不生成无意义备份。

结构迁移只增加归属元数据：历史会话归默认项目，未关联的旧自建配方在首次迁移时关联默认项目。不会把现有图片自动分到“蛋/塑料”，不会移动 ENVI、合并标签或改写已保存标注/模型。

原生固定操作 `project_migration_preview` 对应只读接口：

`GET /api/v1/agent/projects/migration-preview`

它提供现有数据、会话和标签的归属清单，状态为 `preview_only`。没有自动应用入口。真正拆分旧数据必须另行明确目标项目、标签映射、配方、连续量、历史实验及混合归属资源，作为独立迁移交付。拆分后，旧草稿/确认中的父引用会在执行前重新校验，不允许静默替换成员继续执行。

## 验证

在正常 Windows 用户上下文、已激活虚拟环境下运行：

```powershell
python scripts/audit_project_resources.py --check
python -m pytest -q --basetemp=.tmp-project-suite
node --test --test-concurrency=1 tests/*.test.mjs
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

测试临时目录必须是仓库内专用目录，不能指向真实数据。测试包含临时测试密钥的 DPAPI 往返；受限沙箱可能无法执行该 Windows 系统调用。

重点验收 `test_project_scopes.py`：两个项目、项目内 D 编号、跨会话共享、cube/recipe/model UUID 绕过、跨项目重复导入、HTTP 与会话身份、无标注新数据推理防退化、后台归档、并发标签、旧引用失效、一致性备份及逐步确认。前端测试另验证项目切换、新会话身份和旧目录延迟响应。

`test_study_project_lifecycle.py` 使用非默认项目的 ENVI/ROI、3 折和两个候选，覆盖草稿创建即校验、桌面停留默认项目时由会话确认执行、重复确认、旧卡片重启恢复、归属冲突、事务回滚及登记失败后的锁释放。历史 Study 的结果和中断恢复另由 Study 回归用例验证。无需跑 225 个候选来验证归属机制；本测试不证明候选模型的科学有效性。

自动测试使用临时数据和脚本模型，不调用真实模型网关，不代表已经用真实 41 张数据完成七步训练，也不代表重新打包了安装版。
