## §0 前提与判定轴

**换皮方案假设**（与 P3 同）：只新增 skin 文件 + 各加一行 import；**保留现有 `className`**、保留文案与 `aria-label`、保留 JSX 结构与逻辑字面量。

**判定轴与 P3 表的差别**：P3 表用的是"触碰与否"（假设可能改 TSX）；本表用 **"受影响 / 隐含约束"**——因为 P4 的授权方案更窄（只加两个 CSS 文件 + 两行 import），TSX 内容不可能被改到：

| 判定 | 含义 |
|---|---|
| **不受影响** | 授权方案下断言恒绿，无需任何同步 |
| **隐含约束** | 断言本身不会红（它读的是**旧 CSS 文件**），但新 skin 必须遵守同一条禁则，否则"意图失守"——需自备机器门 |

## §3 对 P4 卡的四条推论

1. **断言不是风险，样式结构才是。** P3 的 `annotation.css` 有 `--ann-*` 变量体系（一条变量换全局主色）；**P4 的两个 CSS 都没有任何变量**（`grep --` 结果 0）。所以 P4 拿不到"变量优先"这个省事路径，必须逐条写规则。

2. **禁则必须自备机器门。** `panel.test.ts:63` 读的是 `./preprocess.css` 这个具体文件；新增的 `preprocess-skin.css` **不在任何断言范围内**。P4 的验收里要有一条：
   `grep -cE 'position:\s*fixed|100vh|z-index' preprocess-skin.css = 0`，`model-skin.css` 同理。**意图门不变成断言门，就只是一句劝告。**

3. **选择器结构：全部是"元素/类前缀"型，没有裸类为主的体系。** 实测：
   - `preprocess.css`：`.preprocess-panel h2`、`.preprocess-panel input[type=number]`、`.pp-layout aside > section`、`.pp-fields, .pp-target`、`.pp-editor li`
   - `modeling.css`：`.model-panel header`、`.model-panel label input, .model-panel label select`、`.model-charts`、`.model-chart-scope`
   → skin 规则一律加 `.preprocess-panel` / `.model-panel` 前缀：对已有前缀的规则**同特异性、后加载胜出**；对裸类（`.pp-layout` / `.model-charts`）**0-2-0 直接胜出**。

4. **布局现值要进 P4 卡事实表**（P3 卡漏了这条，靠 178/236 有原型背书才侥幸无恙）：
   - `preprocess.css:4` `.pp-layout { grid-template-columns: minmax(190px,240px) minmax(0,1fr) }`
   - `modeling.css:1` `.model-panel { padding:1.25rem; max-width:76rem; margin:auto }`
   换皮若改这两处，必须给出原型出处行号。
