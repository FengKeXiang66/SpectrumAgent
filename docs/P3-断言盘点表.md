## §0 换皮方案假设（第三列依赖这个前提，不写则无法判定）

P3 换皮定义为：

1. **只做加法**——新增包裹层、新增布局类（`p-` 前缀）、新增 CSS 规则
2. **保留现有 `className`**——不重命名、不删除
3. **保留文案与 `aria-label`**——一字不改
4. **保留 JSX 结构与逻辑字面量**——条件表达式、事件处理器、prop 传递不动

在这个前提下：**断言对"新增"免疫，只对"改名/删除"敏感。**

## §3 对 P3 卡的三条推论

1. **"保 className" 是 P3 的第一硬约束，不是可选风格。** 一旦决定重命名（例如把 `annotation-card` 改成 `p-card`），`projection:20/21`、`working:93` 立刻转成"必须同步"，且**任何引用旧类名的断言都可能连带红**——本表只覆盖 5 个文件，`panel.test.ts`（14 行 / 26 次）与 `SettingsPanel.test.ts`（15 处）另计 **41 处**不在本表范围。

2. **换皮的实现路径应当是"加规则"而不是"改类名"**：新增一个 `annotation-skin.css`，用现有类名选择器覆盖样式。这样 65 处断言一处不动，P3 的验收门可以保持"零授权同步"。

3. **`annotation.css` 的禁用规则要一起看**：`working.test.ts:93` 禁 `position: fixed`，`panel.test.ts:63` 禁 `position:fixed|100vh|z-index`（针对 `preprocess.css`）。P3 新增的皮肤文件若用了 `z-index` 做层级，需要先确认没有同类断言扫它。
